# 民生证券厦门分公司 · 招聘候选人库

一个纯静态网页平台，用于汇集招聘专员从 **BOSS直聘 / 猎聘 / 智联招聘** 三个渠道搜集到的候选人简历（截图、PDF 等格式不一），统一整理成标准化字段，方便按关键词（如公司名）搜索、按获取时间排序、点击查看候选人完整信息。

无需数据库、无需后端服务，所有数据存放在 [`data/candidates.js`](data/candidates.js) 中，部署到 GitHub Pages 即可直接访问。

**线上地址：** https://chennengjie-prog.github.io/msxm-recruit-candidates/ （电脑和手机浏览器都能直接打开）

> ⚠️ 当前仓库按你的要求设置为**公开仓库**。`data/candidates.js` 里的姓名、工作履历会被任何人搜索到；详情页的电话号码默认做了打码处理（如 `138****5678`）。如果后续要放更敏感的信息（身份证号、完整电话等），建议改用私有仓库 + 内网访问，而不是继续放在公开仓库里。

## 首页标准化字段说明

首页表格只展示招聘专员最关注的字段（获取时间、姓名、来源、**联系方式获取情况**、学历、证券从业资格证、院校、目前单位/职位、工作年限、意向职位、现居地、状态），默认按 **获取时间倒序**（最新的排最前）。点击某一行会跳转到该候选人的详情页，展示完整信息：联系方式、全部工作经历时间线、教育经历、资格证书、自我评价、招聘备注等。

### 联系方式获取情况（重点字段）

简历来源不同，能不能直接联系到候选人差别很大：BOSS直聘/猎聘上很多简历在没有"沟通/解锁"之前只显示部分信息、真实姓名也可能被隐藏（比如显示成"叶先生"）。为了让招聘专员一眼看出哪些候选人可以直接打电话、哪些还需要想办法要联系方式，首页表格和详情页都用醒目标签区分：

- **绿色标签（显示脱敏手机号）**：`contactObtained: true`，已经拿到电话，可以直接联系。
- **黄色"待获取"标签**：`contactObtained: false`，目前只有平台上公开的简历信息，电话/邮箱还没拿到，需要招聘专员自己想办法（如 BOSS 上"继续沟通"/"帮我联系"、猎聘约聊等）。这种情况下 `name` 字段通常也只是平台显示的称呼（如"叶先生"），不是真实姓名，详情页会在姓名旁加提示。
- 首页工具栏有"仅显示已获取联系方式"勾选框，可以快速筛出已经能联系上的候选人。
- 一旦后续要到了联系方式，记得把该候选人的 `contactObtained` 改成 `true`，补上真实 `name`、`phone`（`email` 如有也补上）。
- **首页"待获取"按钮**：招聘专员在首页拿到某个候选人的电话后，可以直接点"+ 录入联系方式"按钮当场输入，不用跳转详情页也不用改代码。但这个输入**只保存在当前浏览器**（用的是 localStorage，网站本身是静态页面、没有后端，浏览器没法帮你写回 GitHub），换一台电脑或清空浏览器数据就看不到了。想让所有人都看到，还是要把号码按上面的方式正式写进 `phone` 字段、`contactObtained` 改成 `true`，推送到 GitHub。

## 如何添加真实候选人数据

简历原始格式多是截图/PDF，没有统一结构，所以需要招聘专员人工把关键信息摘录填入 `data/candidates.js`。每个候选人是数组里的一个对象，字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 唯一编号，如 `c007`，不能重复 |
| `name` | 姓名 |
| `source` | 简历来源，固定填 `BOSS直聘` / `猎聘` / `智联招聘` 之一，决定列表页标签颜色 |
| `acquiredDate` | 获取简历的日期，格式 `YYYY-MM-DD`，决定首页排序 |
| `resumeContact` | 简历联系人，即这份简历是哪位招聘专员对接/整理的，固定填 `陈彦汐` / `李祖荃` / `蔡家宝` 之一，首页有对应的筛选按钮 |
| `activityStatus` | 候选人在招聘平台上的活跃状态，如 `本周活跃` / `2周内活跃` / `刚刚活跃`，直接照搬平台显示的文案即可 |
| `gender` / `age` / `location` | 性别 / 年龄 / 现居地 |
| `education` / `school` / `major` | 学历 / 毕业院校 / 专业 |
| `currentCompany` / `currentPosition` | 目前或最近就职单位 / 职位 |
| `yearsOfExperience` | 工作年限（数字） |
| `expectedPosition` / `expectedSalary` | 意向职位 / 期望薪资 |
| `contactObtained` | 是否已拿到联系方式，`true` / `false`，决定首页"联系方式"列和详情页显示脱敏手机号还是"待获取"标签 |
| `phone` / `email` | 联系电话 / 邮箱；`contactObtained` 为 `false` 时留空字符串即可，电话详情页会自动打码显示 |
| `jobSeekingStatus` | 候选人在招聘平台上标注的求职状态，如 `在职-考虑机会` / `离职-随时到岗`，没有就留空字符串 |
| `status` | 招聘专员自己的跟进状态，如 `待联系` / `已初筛` / `面试中` / `已淘汰` / `已录用`，可自行定义 |
| `hasSecQualification` | 是否有证券从业资格证，填 `true` / `false`，首页表格和详情页都会显示"有/无"标签，也可以用页面上的"仅显示持证候选人"勾选框筛选 |
| `certificates` | 资格证书数组，如 `["证券从业资格证", "基金从业资格证"]` |
| `selfEvaluation` | 自我评价（从简历摘录或招聘专员总结） |
| `notes` | 招聘专员备注 |
| `workExperience` | 工作经历数组，每项含 `company` / `position` / `period` / `description` |
| `educationExperience` | 教育经历数组，每项含 `school` / `degree` / `major` / `period` |

**关键词搜索**会匹配姓名、来源、学历、院校、专业、目前/意向公司与职位、现居地、状态、证书、自我评价、备注，以及**全部历史工作经历里的公司名和描述**——所以搜"平安银行"能搜到所有曾经或目前在平安银行工作过的候选人，不只是当前单位是平安银行的人。

可以直接复制 `data/candidates.js` 里现有的一条记录作为模板，改成新候选人的信息，保存即可。

## 本地预览

直接双击 `index.html` 用浏览器打开即可看到列表页，不需要额外启动服务器（候选人数据是通过 `<script src="data/candidates.js">` 内嵌进页面的，不受浏览器本地文件读取限制）。

如果更习惯用本地服务器方式预览，也可以在本目录下执行：

```bash
python -m http.server 8000
```

然后浏览器打开 `http://localhost:8000`。

## 部署到 GitHub Pages

1. 在 GitHub 上新建一个仓库（当前按你的选择是**公开仓库**）。
2. 把本目录内容推送到该仓库的 `main` 分支。
3. 进入仓库 Settings → Pages，Source 选择 `main` 分支 / 根目录，保存。
4. 几分钟后即可通过 `https://<你的用户名>.github.io/<仓库名>/` 访问候选人库。
5. 之后每次更新 `data/candidates.js` 并推送到 GitHub，网页会自动更新（无需重新部署）。

## 后续可以扩展的方向（按需再做）

- 如果人工编辑 JSON 不方便，可以做一个 Excel 模板 + 转换脚本，招聘专员填 Excel，脚本自动生成 `candidates.js`。
- 如果简历原件（截图/PDF）也要能在详情页直接查看，可以把文件放进仓库并在候选人记录里加一个 `attachments` 字段链接过去；但需注意这些原件通常包含更完整的身份信息，公开仓库下风险更高。
- 如果候选人数量变多，可以加分页或虚拟滚动；目前是纯前端遍历，几百条以内不会有性能问题。
